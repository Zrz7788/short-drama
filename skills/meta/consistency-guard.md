# 一致性守卫 — 元技能

## 何时使用

贯穿全流程。**只要涉及同一个实体出现在多个地方，就归这条管。**
具体说：`art`（出参考图）、`prompts`（组装提示词）、`keyframes`（出首帧）、
`motion`（出视频）四个阶段。

## 为什么单独立一条

仿真人短剧的**第一号失败模式**是主角跨镜头、跨集崩脸。它的代价极高：
拍完 20 个镜头才发现主角变成三个人，等于全部重抽。而且它**不会自己暴露**——
每一帧单看都正常，只有连起来看才发现。

## 四条铁律

### 1. 参考图链必须闭合

一致性靠一条链传递，任何一环断了就漂：

```
定妆照 portrait
   ↓ 作为图生图输入
派生视角 fullbody→headshot
   ↓ 冻结（approved=1）
首帧图 shot.keyframe_path
   ↓ 作为参考图
视频 generation
```

**每一环都要显式传上一环的产物。** 第 6 阶段的提示词里带实体描述文本，
第 7 阶段的首帧把定妆照当参考图传进去——两者缺一不可：

- 只传文本不传图 → 模型自由发挥，长得像但不是同一个人
- 只传图不传文本 → 角度变了就漂

### 2. 描述块必须逐字一致

第 6 阶段的提示词是**确定性拼接**，实体描述从 `entity.description`
逐字复制。这是刻意的，而且脚本里有**机械校验**：

> 任何实体的描述块没有原样出现在提示词里，脚本立刻报错。

**看到这个报错不要绕过它。** 它通常意味着提示词模板被改坏了，
或者有人在中间加了个"润色"步骤。那正是崩脸的起点。

```sql
-- 自查：有没有镜头的提示词漏了实体描述
SELECT s.seq, e.name FROM shot s
  JOIN shot_entity se ON se.shot_id = s.id
  JOIN entity e ON e.id = se.entity_id
 WHERE s.episode_id = ?
   AND (s.prompt IS NULL OR instr(s.prompt, e.description) = 0);
```

### 3. 审完必须冻结

`art` 阶段产出参考图后，人审通过要把 `entity_ref.approved = 1`，
并指定 `is_primary = 1` 的那张为锚点。

**冻结之后禁止重出。** 没有这个动作，第 30 集有人手贱重出一次定妆照，
后面全部崩——而且要很久才发现。

```sql
-- 冻结状态自查
SELECT e.name, r.view, r.approved, r.is_primary FROM entity_ref r
  JOIN entity e ON e.id = r.entity_id
 WHERE e.project_id = ? ORDER BY e.name, r.view;
```

### 4. 高风险场景要认得出来

不是所有镜头都同样危险。按危险度分配注意力和抽卡预算：

| 场景 | 风险 | 对策 |
|---|---|---|
| 正脸特写 | 五官全暴露，差异最明显 | `draft` 多抽（4-6 次） |
| 两人同框 | 可能出现"融合脸" | 负面词加 `人物融合`、`人数变化` |
| 侧脸转正脸 | 中途换角度容易换人 | 加长单镜时长，或拆成两个镜头 |
| 快速运动 | 面部模糊，反而容错高 | 可以少抽 |
| 背影 / 远景 / 手部 | 不露脸 | `direct` 直出，别浪费预算 |

第 6 阶段会自动给含多个 `subject` 的镜头追加一致性负面词。

### 5. 约束要写成具名正面锁，不是尾部负面词

来源见 `knowledge/02-模型与成本/Seedance提示词与连续性锁定.md`。核心观念转变：

> **约束不属于末尾的负面提示词。它们属于「具名块」，且通常用正面措辞陈述"什么保持不变"。**

对我们最有用的几把锁：

| 锁 | 用在短剧的哪里 |
|---|---|
| `SCREEN DIRECTION` | 对话正反打的轴线。"A 永远在画面左，B 永远在右，绝不互换" |
| `COUNT LOCK` | "画面里正好两人，绝不出现第三个人，镜面/倒影里不能多出人" |
| `STILLNESS LOCK` | "不发生什么"的清单 |
| `POSITIVE LOCKS` | 结尾用正面措辞重申跨镜头保持不变的东西 |
| `IDENTITY / NO-IP LOCK` | "完全原创、凭空发明的脸"，无商标、无可读文字 |

### 6. 状态单调性：最便宜的连续性技巧

**状态只前进，不回退。** 湿了只能更湿。逐镜头把进程写出来，
能阻止模型在下一个镜头**"顺手把你的角色清理干净"**。

短剧里的用法：衣服越穿越乱、伤口越来越重、雨越下越大、手里的信越攥越皱。
**这既是叙事，又是连续性**——一句话办两件事。

### 7. ⚠️ 用「上一镜尾帧」承担连续性，是错的

**这一条推翻了我们原来的设计，记在这里免得有人改回去。**

我们原来第 9 阶段默认把相邻镜头串起来（后一镜首帧 = 前一镜尾帧）。
但一部已发布的 110 分钟 Seedance 长片**全片禁止使用起始帧**，
连续性由**资产**承担——因为上一镜的最后一帧**会拖带它自己的漂移**。

而且逻辑上本来就别扭：**短剧镜头之间大多是硬切**，机位和角度都变了，
"后一镜从上一镜最后一帧开始"在物理上不成立。

**正确做法**：

| 情形 | 做法 |
|---|---|
| 默认（硬切） | **断开**。连续性靠角色资产 + 具名锁 + 状态单调性 |
| 真实延续（同机位同动作，长镜头拆分） | 串联，`continues_from` 指向上一镜 |
| 单个镜头里有坏掉的元素 | 尾帧当**点修复**手段，不是连续性方法 |

`frames.py --no-continuity` 现在是**默认该走的路**，而不是例外。

## 出问题时的处置

| 现象 | 优先怀疑 | 处置 |
|---|---|---|
| 首帧图里角色不像定妆照 | 参考图没传到，或传错了 | 回 `keyframes`，**别去跑视频** |
| 同一角色在不同镜头差异明显 | 提示词里描述块不一致 | 查上面的自查 SQL，回 `prompts` 重跑 |
| 派生视角之间漂了 | 没有以基底图为参考图生成 | 回 `art` 的 `scenes`/`characters` 子阶段 |
| 某一集整体看着不对 | 定妆照被重出过 | 查 `entity_ref.created_at`，回滚 |
| 两人同框出现融合脸 | 缺负面词 | 回 `prompts`，确认 `人物融合` 在负面词里 |

**共同点：所有处置都是回到更早、更便宜的阶段。** 在视频阶段修一致性问题，
是最贵的做法，而且效果最差。

## 常见陷阱

- **跳过场景素材。** 只有一张正面图，换个角度就是重新想象一个空间
- **改完实体描述不重跑第 6 阶段。** 提示词里还是旧描述，链就断了
- **审完不冻结。** 后面任何人都能重出，一致性没有保障
- **在视频阶段修一致性。** 首帧阶段改一次 ¥0.2，视频阶段改一次 ¥5
- **只给主角做一致性。** 有台词的配角同样跨镜头出现，同样会崩

## 质量门禁

- 每个 `main` 实体有 portrait + front + side + back，且全部 `approved=1`
- 每个 `main` 实体有一张 `is_primary=1` 的锚点图
- 每张首帧图的生成请求里带了至少 1 张实体参考图
- 每个镜头的提示词里，其关联实体的 `description` 逐字出现
- 含多个 `subject` 的镜头，负面词里有 `人物融合`
