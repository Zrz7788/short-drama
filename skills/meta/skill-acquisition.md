# 技能获取 — 元技能

## 何时使用

**当你发现现有技能覆盖不了某个需求，而这个缺口是可复用的**——不是一次性任务。

典型场景：
- 要接一个新的模型/供应商，但不知道怎么把它用好
- 某个技巧反复出现（比如跨镜头一致性），值得固化下来
- 联网查到一个方法，但下次还会用到

**不要**为这些造技能：一次性任务、已被现有技能覆盖的、纯工具配置。

---

## 一、四层技能（照 OpenMontage 的分层，按我们的情况落地）

| 层 | 位置 | 用途 | 谁能自动看到 |
|---|---|---|---|
| Stage director | `skills/pipelines/short-drama/` | 某阶段怎么执行 | 执行层按清单读 |
| Meta skill | `skills/meta/` | 跨阶段协议 | 执行层按需读 |
| **Technique skill** | **`skills/techniques/`** | **某个模型/工具怎么用好** | 按需查 |
| **DSH skill** | **`.dsh/skills/`** | **智能体必须随时知道的** | **自动进目录** |

**最后两层的区别很重要**：

- `skills/techniques/` 是**库**——几十个都可能，按需查，不占智能体的注意力
- `.dsh/skills/` 是**随身携带的**——自动出现在技能目录里。**只放少数几条**，
  否则会把目录淹掉，反而每条都用不好

提升路径：项目级临时技能 → `skills/techniques/` → （确实常用才）`.dsh/skills/`。

## 二、来源可信度分级

**先看来源，再看内容。** 内容写得再漂亮，来源不可靠就不该进库。

| 级别 | 来源 | 处理 |
|---|---|---|
| **一手** | 厂商官方文档、官方开源实现、官方提示词指南 | 可直接采用，仍需标注版本日期 |
| **有据的二手** | 引用了具体一手来源、且说明了测试量 | 采用，标注"经 X 转述" |
| **无据的二手** | 没说依据、数字互相矛盾 | **不采用**。这类在 AI 视频领域尤其多 |
| **营销内容** | 只讲能力不讲失败模式 | 不采用 |

> 我们踩过的实例：网上关于火山方舟视频计费的 AI 生成文章，
> **同一个页面里出现"10 秒视频消耗 2200 tokens"和"5000 tokens"两种说法**。
> 这不是笔误，是编的。单价只认控制台。

## 三、质量门禁（可执行）

已经写成脚本：`tools/install_skill.py`。**门禁不是靠感觉，是跑出来的。**

```powershell
# 评估候选（不安装）
python tools\install_skill.py --tar <tarball> --list
# 安装指定包
python tools\install_skill.py --tar <tarball> --install <名字...>
# 从 URL 装单个
python tools\install_skill.py --from-url <url> --name <名字> --dry-run
```

### 硬性（不过就拒绝）

| 检查 | 理由 |
|---|---|
| 有 `SKILL.md` | 没有它，技能系统加载不了 |
| 有 YAML frontmatter，含 `name` + `description` | 智能体靠它判断"何时该用" |
| `description` ≥ 40 字符 | 太短等于没写 |
| 正文 ≥ 1200 字符 | 低于此多半是壳 |
| **无自我废弃标记**（`[DEPRECATED]` 等） | 作者自己都说别用了 |

### 提示（只标记，交人判断）

- 体积异常大（>5 MB，多半混了媒体资源）
- 没有出处 URL
- 没有「陷阱」小节
- 没有表格（结构化信息少）
- **提到已废弃的其他技能包**——附原文上下文，由人判断是"支持"还是"依赖"

### 相关性**不进门禁**

脚本判断不了"这个技能对我们这条竖屏短剧流水线有没有用"。它只把描述打出来，
**由人决定**。把相关性做成自动判断只会制造假信心——而且会静默地筛掉你真正需要的东西。

## 四、两条踩出来的教训

### 教训一：过度拒绝比放过更危险

第一版的依赖检查做成了**硬性拒绝**：只要描述里出现已废弃包的名字就拒。
结果 `seedance-2-0`、`visual-style`、`media-use` 这些**好包全被拒了**。

原因：它们在正文里把 HeyGen 列成**反例**——`seedance-2-5` 原文就写着
*"Do not invent a Replicate, HeyGen, or Higgsfield identifier"*。

**名字出现在文本里 ≠ 依赖它。**

而且失败方向很关键：门禁太松你会很快发现（装了个没用的），
**门禁太紧是静默地丢掉好材料，你可能永远不知道丢了什么。**

所以凡是"可能误伤"的检查，一律降级为标记。

### 教训二：先看作者有没有自己说别用

`heygen` 这个包的描述第一句就是 `[DEPRECATED] Use create-video instead`。
**作者自己标注废弃是最强的信号**，而且它是免费的——先查这个。

**评估 91 个包的结果**：84 通过，7 拒绝。

| 被拒的包 | 原因 |
|---|---|
| `heygen` | 自我标注 `[DEPRECATED]` |
| `threejs-postprocessing` | 同上 |
| `ai-video-gen` | 同上 |
| `gsap-performance` | 同上 |
| `gsap` | 没有 `SKILL.md`（91 个里唯一一个） |
| `canvas-procedural-animation` | 正文仅 1088 字符 |
| `web-design-guidelines` | 正文仅 915 字符 |

## 五、安装后必须做的三件事

1. **登记出处**：`skills/techniques/_provenance.json` 记下来源仓库、路径、许可、体积、
   警告项。**不知道东西是哪来的，就没法判断它过时没有**
2. **核一遍许可**：AGPL/GPL 的代码不能随便并进要商用的项目。
   纯文档参照一般没问题，但**要留痕**
3. **实测一次**：装完不要就信了。用它做一件小事，看方法是否真的成立

## 七、常见陷阱

- **把相关性做成自动判断。** 会静默筛掉你需要的东西
- **门禁只做单包检查。** 漏掉"依赖了已废弃的包"这种情况
- **反过来，把可能误伤的检查做成硬拒。** 见教训一
- **装了不登记出处。** 半年后不知道它是哪来的、过时没有
- **往 `.dsh/skills/` 里塞太多。** 那是随身层，塞满了每条都用不好
- **只看描述就装。** 描述是作者写的广告，正文才是内容

## 质量门禁

- 新增技能跑过 `tools/install_skill.py` 且通过硬性检查
- 出处已登记进 `_provenance.json`
- 许可已确认，且留痕
- 相关性由**人**确认过，不是脚本判断的
- 只有确实常用的才提升到 `.dsh/skills/`
