# 门禁协议 — 元技能

> 形态参照 OpenMontage 的 `skills/meta/checkpoint-protocol.md`，但按我们的实际情况
> 重写。**他们的实现依赖 `lib/checkpoint.py`，我们还没有执行层**——本文件是执行层
> 的规格说明，不是已生效的机制。落地前它约束不了任何东西。

## 什么时候用

一个阶段**做完并通过审查之后**。门禁是流水线的存档点：它让失败可续跑、
让人工可介入、让改动有审计痕迹。

## 协议

### 第 1 步：读清单里的两个开关

从 `pipeline_defs/short-drama.yaml` 读当前阶段：

```yaml
- name: script
  checkpoint_required: true      # 要不要存档
  human_approval_default: true   # 要不要问人
```

| `checkpoint_required` | `human_approval_default` | 动作 |
|---|---|---|
| true | true | 存档 + 停下来等人批 |
| true | false | 存档 + 自动继续 |
| false | * | 不存档（少见） |

### 第 2 步：进入阶段时先写一条 `in_progress`

**任何阶段一进去就先写 `in_progress`。** 这是告诉人（和看板）"这一阶段是活的，
不是卡住了"。确定性比速度重要。

### 第 3 步：长阶段每完成一个显著条目就写一次

`motion`（抽卡循环）和 `keyframes`（逐镜出图）这类阶段可能因为 API 报错、
限流、会话中断而在中途死掉。要能**从失败的那一镜续跑**，而不是从头再来：

- 每成功出一个镜头/一条样片，就更新一次 `in_progress`
- 续跑时先读现有的 `in_progress`，跳过已完成的镜号

我们已经有现成的判据可用，不需要额外记状态：

```sql
-- motion 阶段续跑的判据：哪些镜头已有成功记录
SELECT s.seq FROM shot s
 WHERE s.episode_id = ?
   AND NOT EXISTS (SELECT 1 FROM generation g
                    WHERE g.shot_id = s.id AND g.status = 'succeeded');
```

### 第 4 步：人工门禁

**清单里的值是绑定的。** `human_approval_default` 是这一阶段是否要人批的
唯一真源。本协议不覆盖它，你也不覆盖它——**没有"这次情况特殊"**。

要人批时：

1. **状态写 `awaiting_human`**，不是 `completed`
2. **呈现摘要**：

```
## 阶段完成：[阶段名] — 等待你的批准

### 产出摘要
[关键信息：集数、场数、镜头数、时长、关键决策]

### 审查发现
[审查结论：N 个必须改（已改）、N 个建议]

### 目前花费
[已花 / 预算，按类别分解]

### 需要你做的事
请审阅并批准继续，或给出修改意见。
```

3. **结束回合。** 在同一轮里继续做下游工作就是**跳门禁**。
   "呈现完顺手继续"不叫等待——回合必须以提问结束，下一步动作必须由人的回复触发。

4. **人的回复**：
   - **批准** → 状态改写 `completed`，加 `human_approved=1`，进入下一阶段
   - **要求修改** → 回到该阶段的导演技能，带反馈重做，重审，重存档
     （被取代的记录归档到 history，**永不销毁**）
   - **中止** → 停

5. **门禁是逐道的。** 之前批过一次，哪怕话说得很宽（"看着不错，全权交给你了"），
   **也不覆盖后面的门禁**。除非当时就把这次预授权记进 `decision_log`
   （`category: "approval_policy"`）——没有那条记录，就每道门都停。

### 第 5 步：一条我们特有的硬规则

**`keyframes` 门禁审查首帧图，且不许为了"挣得"这次审查而先跑视频。**

审查面是首帧图本身（和相关实体的参考图），**不是渲染出来的片段**。
在 `keyframes` 阶段里跑视频，就是在跳用户本该把守的那道门。
视频是 `motion` 阶段的事，且只在首帧门禁通过之后。

理由很直接：首帧 ¥0.2/张，视频 ¥4-5.8/条，差 20-30 倍。
用贵的产物去换一次本该用便宜产物换来的审查，是把成本结构搞反了。

## 关键原则

1. **完成的工作一定要存档。** 即使 `checkpoint_required: false`，只要这阶段花了
   显著时间或钱，也值得存一次。丢工作比多一个文件糟得多。

2. **创作阶段绝不跳过人工审批。** `script` 和 `cast` 决定后面的一切。
   为了省时间冲过去，产出的是没人想看的东西。

3. **摘要里必须带花费快照。** 人在批准昂贵下游（`motion`、`assemble`）之前，
   应该知道已经花了多少、还剩多少。

4. **存档是为了续跑。** 在 `assemble` 崩了，重启应该从 `assemble` 接上，
   而不是从 `script` 重来。这是整件事的意义。

5. **要人批的时候要透明。** 别只给产出——把审查发现、花费、以及你的顾虑一起给。
   帮人做有依据的决定。
