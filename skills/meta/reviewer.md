# 审查 — 元技能

## 何时使用

**每个阶段做完之后、写 checkpoint 之前。** 审查不通过就不该往下走。

## 两级结论

| 级别 | 含义 | 处置 |
|---|---|---|
| `critical` | 不修就会污染下游 | **必须修完才能进下一步** |
| `suggestion` | 会更好，但不会毁掉下游 | 记录，可选 |

**不要有第三级叫"还行"。** "还行"不是一个结论，它是没审查。

## 审查协议

### 1. 先看 `success_criteria`，那是硬判据

清单里每个阶段都写了 `success_criteria`——**那些是机器可判的**。
先跑它们，任何一条不过就是 `critical`。

### 2. 再看 `review_focus`，那是需要判断的

清单里的 `review_focus` 是给人看的关注点，通常是自然语言、需要判断的。
这一层交给审查者（人或智能体）逐条过。

### 3. 结论必须可执行

**坏的结论**："剧本不太行。"
**好的结论**："第 3 场的钩子在第 12 秒才出现，前 11 秒是铺垫。要求：把钩子提到 0-3 秒，
或把第 3 场与第 1 场对调。"

判据：**拿到这条结论的人，能不能不改一个字就动手？** 不能，就重写结论。

### 4. 审查要带证据

每条结论附上**具体位置**：哪一场、哪一镜、哪个实体、哪一行字段。
不指明位置的结论无法验证是否已修复。

### 5. 审查完写进 checkpoint 的 metadata

```json
{
  "review": {
    "critical": [{"where": "S03", "issue": "...", "fix": "..."}],
    "suggestions": [{"where": "S07", "note": "..."}],
    "cost_snapshot": {"spent_cny": 12.4, "budget_cny": 200}
  }
}
```

## 各阶段的审查要点

### spec（定规格）

| 要点 | 反例 |
|---|---|
| 分辨率定了没有 | "看情况"——它决定后面能用哪些模型档位 |
| 集数与单集时长都定了没有 | 只问"80 秒多少钱"缺一个变量 |
| 音频路线定了没有 | 它决定台词怎么写，后改要返工 |

### script（剧本）

| 要点 | 判据 |
|---|---|
| 钩子在 0-3 秒 | 不是"开头有点慢" |
| 台词每句 ≤ 12 字 | 数得出来 |
| 集尾扣子是新信息 | 不是"事情没说完" |
| 各场时长合计 | 与目标偏差 ≤ 20% |

### cast（实体与分级）

| 要点 | 判据 |
|---|---|
| 分级克制 | `background` 级每一集应该很少 |
| `description` 是可粘贴的块 | 含具体特征，不含"气质很好" |
| 三类都提了 | 人物/布景/道具，道具常是剧情核心 |

### art（参考图）

| 要点 | 判据 |
|---|---|
| 定妆照清晰可辨 | 五官/发型/服装肉眼可辨 |
| 三视图以定妆照为参考图 | 生成请求里有 `image` 字段 |
| **审完冻结** | `approved=1` 且 `is_primary=1` |

### storyboard（分镜）

| 要点 | 判据 |
|---|---|
| 抽卡策略分化 | `draft` 与 `direct` 都存在 |
| 每个镜头挂了实体 | 含纯空镜（挂布景） |
| 实体名逐字存在 | 脚本已校验，未报错即可 |

### prompts（提示词）

| 要点 | 判据 |
|---|---|
| 实体描述逐字内联 | 脚本的机械校验没报错 |
| 多主体有融合负面词 | `人物融合` 在 `negative_prompt` 里 |

### keyframes（首帧图）★ 最关键

| 要点 | 判据 |
|---|---|
| 角色就是定妆照那个 | 参考图已作为图生图输入 |
| 构图/灯光符合 `lighting` | 肉眼判断 |
| **不要为了审查先跑视频** | 见下 |

> **禁止为了"挣得"这次审查而先跑视频。** 审查面是首帧图本身，
> 不是渲染出来的片段。在 `keyframes` 阶段里跑视频 = 跳用户本该把守的门。

### motion（视频）

| 要点 | 判据 |
|---|---|
| 每镜有选中项 | `selected_generation_id` 非空 |
| 账目自洽 | `cost_ledger` 与调用记录合计一致 |
| 预算未超 | 或已被显式放行 |

### continuity（衔接）

| 要点 | 判据 |
|---|---|
| 续接链成立 | 后一镜首帧 == 前一镜尾帧 |
| 硬切处已断开 | 该镜 `continues_from` 为空且是有意的 |

### assemble（成集）

| 要点 | 判据 |
|---|---|
| 时长对得上 | 与各镜素材之和偏差 ≤ 0.5 秒 |
| 字幕正确 | 烧录成功，中文字体正常 |
| 缺镜已确认 | 默认拒绝出残缺版 |

## 常见陷阱

- **审查变成点头。** 每阶段都写"通过"，等于没审
- **结论不可执行。** "不够好"没法修
- **`critical` 里混进 `suggestion`。** 会让该修的和小事混在一起，最后都没修
- **审查完不记进 checkpoint。** 下一个人（或下一次续跑）不知道审过什么

## 质量门禁

- 每个阶段的 `success_criteria` 都逐条跑过
- 所有 `critical` 都已修复（不是"已记录"）
- 每条结论都指明位置
- 审查结果写进了 checkpoint 的 `metadata.review`
