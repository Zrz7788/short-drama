# 首帧导演 — 短剧流水线

## 何时使用

提示词定稿之后、视频生成之前。

**这是成片前最后一个便宜的关卡，也是整条流水线性价比最高的一环。**

## 前置

| 层 | 资源 | 用途 |
|---|---|---|
| 上游工件 | `shot_prompts`、`reference_sheets` | 提示词 + 参考图 |
| 表 | `shot.keyframe_path` / `image_generation` | 落首帧与生成记录 |
| 工具 | `pipeline/stage_firstframes.py` | 出首帧 |
| 提示词 | `pipeline/prompts/shot_prompt.md` | 组装好的提示词 |

## 为什么这一阶段值得单独立门

**成本差 20-30 倍。**

| | 单价 |
|---|---|
| 首帧图 | **约 ¥0.2 / 张** |
| 视频（Draft 样片） | 约 ¥1.0 / 条（4 秒） |
| 视频（1080P 成片） | 约 ¥5.8 / 条（4 秒） |

正确打法：**在首帧图上抽 10 次（¥2）选最好的一张，再去生视频**——
比在视频上抽 3 次（¥12-17）**又便宜又稳**。

**首帧不对就别去烧视频。** 视频阶段没有便宜的退路。

## 流程

### 1. 参考图必须传进去

每张首帧的生成请求要带实体参考图，按重要性排序，**最多 4 张**：

```
主体（character） → 道具（prop） → 背景（location）
```

**只传文本不传图 → 模型自由发挥，长得像但不是同一个人。**
**只传图不传文本 → 角度变了就漂。** 两者缺一不可。

> 参考图数量不是越多越好。原话：**"一个需要保持一致的元素配一张参考图"**——
> 一张脸、一件道具、一个空间、一种风格。堆一堆互相竞争的脸和道具，
> 产出的连贯性反而**更差**。

Draft 样片用 480P 就够——**看构图和像不像，不需要 1080P**。

### 2. 多抽几张挑

```powershell
python pipeline\stage_firstframes.py --episode-id 1
python pipeline\stage_firstframes.py --episode-id 1 --take 4   # 每镜出 4 张候选
```

这是全片最值得多抽的地方：¥0.2 一张。

### 3. 人审——看什么

| 看 | 判据 |
|---|---|
| **角色是不是定妆照那个** | 五官、发型、服装逐项对 |
| 构图与 `shot_size` 是否一致 | 特写不能出成全景 |
| `lighting` 是否兑现 | 提示词写了侧逆光就得是侧逆光 |
| 空间是不是那个场景 | 墙、窗、纵深要和场景资产对得上 |
| 参考图有没有真的生效 | 不像就回查 `image_generation` 的请求里有没有 `image` 字段 |

## ⚠️ 一条硬性治理规则

> **禁止为了"挣得"这次人工审查而先跑视频。**

审查面是**首帧图本身**（和相关实体的参考图），**不是渲染出来的片段**。
在 `keyframes` 阶段内跑视频 = **跳用户本该把守的那道门**。

理由很直接：**用贵的产物去换一次本该用便宜产物换来的审查，是把成本结构搞反了。**
视频是 `motion` 阶段的事，且只在首帧门禁通过之后。

## 常见陷阱

- **首帧不对就去跑视频。** 最贵的错误。视频阶段改一次 ¥5，首帧阶段改一次 ¥0.2
- **没传参考图。** 角色长得像但不是同一个人
- **参考图堆太多。** 互相竞争，连贯性反而更差
- **只看单张静帧就通过。** 首帧是起点，要想象它动起来是否成立
- **在本阶段顺手跑了视频。** 跳门禁
- **为了省钱只出 1 张。** 这是最不该省的地方

## 质量门禁

- 每个 `shot.keyframe_path` 非空且文件存在
- 每张首帧的生成请求里**至少 1 张实体参考图**（无参考图的需显式记录并说明）
- 每张首帧的参考图 ≤ 4 张
- 人确认**画面里的角色就是定妆照那个**
- **本阶段内没有任何视频生成记录**（`generation` 表无新增）

---

## 门禁提醒（绑定）

本阶段有人工门禁。做完后**结束回合**，等人批。

批准：`python pipeline\run.py --episode-id N --approve keyframes --note "..."`

**这是最后一道便宜的关卡。** 过了这道门，后面每一次返工都是视频的钱。
