# 规格导演 — 短剧流水线

## 何时使用

整条流水线的第一步。**在写一个字剧本之前。**

它只产出三样东西，但这三样后面全都要用，而且**改起来很贵**：分辨率、集数、
音频路线。

## 前置

| 层 | 资源 | 用途 |
|---|---|---|
| 清单 | `pipeline_defs/short-drama.yaml` 的 `models` 段 | 可选模型与档位 |
| 表 | `project` / `decision_log` | 落规格与理由 |
| 知识 | `knowledge/02-模型与成本/单集成本模型.md` | 预算依据 |
| 参考 | `.dsh/skills/ark-seedance` | 模型 ID 与单价 |

## 流程

### 1. 分辨率：它决定了后面能用哪些模型档位

**这一条要在最前面定，因为它会锁死后面所有选择。**

| 想要 | 能用谁 | 备注 |
|---|---|---|
| 480p / 720p | 全部（含 fast / mini） | 便宜但交付感弱 |
| 1080p | **只能 2.5 或 2.0 pro** | fast / mini 传 1080p **返回 400** |
| 4k | 2.5 / 2.0 pro | 单价高 |

竖屏短剧的交付规格一般是 **9:16 / 1080p**。

> ⚠️ **一处必须核实的分歧**：第三方资料称 Seedance 的支持路线只暴露
> 480p/720p，1080p 只在厂商网页平台。这与我们从控制台看到的价目冲突。
> 详见 `knowledge/02-模型与成本/Seedance提示词与连续性锁定.md` 冲突二。
> **插上 key 后第一件事就是核这个**——它是 Draft 三段式的支点。

### 2. 集数：只问「80 秒多少钱」缺一个变量

单集不贵，整部剧才是预算主体。**必须同时问清单集时长与总集数。**

成本粗算（依据 `knowledge/02-模型与成本/单集成本模型.md`）：

```
单集视频成本 ≈ 镜头数 × 时长 × 单价 × 抽卡次数
80 秒 ≈ 20 镜 × 4 秒
2.5 + Draft 抽卡 3 次 ≈ ¥178 / 集
整部 80 集 ≈ ¥15,700
```

### 3. 音频路线：**它决定台词怎么写**

这是最容易被跳过、代价最大的一条决定。三条路：

| 路线 | 口型 | 可控性 | 适用 |
|---|---|---|---|
| **模型原生音频** | 天然对齐，**无对口环节** | 低（换声线/改词重配都难） | **仿真人写实短剧（推荐）** |
| `reference_audio` 驱动 | 你给配音，模型让口型对上 | 中 | 要特定音色 |
| 外部 TTS + 后期对口型 | Wav2Lip / MuseTalk 等 | 高 | 换语言、配音替换 |

**为什么它决定台词怎么写**：

- 走**原生音频**：台词直接写进提示词，由模型念。所以台词要**短、要有停顿标点**
  （叹号加强语气、省略号造悬念、破折号拉长元音、逗号自然停顿）
- 走**外部 TTS**：台词要单独整理成配音表，逐句标声线与情绪，
  然后 `adelay` + `amix` 铺到时间轴

**推荐：仿真人短剧走原生音频。** 理由很直接——**它没有"对口"这个环节**。
ffmpeg 从来不做口型对齐，它只做时间轴与混音；靠 ffmpeg 对口型是选错了工具。

### 4. 落库与记录

```sql
UPDATE project SET aspect_ratio='9:16', target_episode_seconds=80 WHERE id=?;
INSERT INTO decision_log (episode_id, stage, category, decision, alternatives,
                          rationale, confidence, source) VALUES (...);
```

**三项各记一条决策**（分辨率 / 集数 / 音频路线），带备选与理由。
半年后回看"当时为什么选原生音频"，答案在这里。

## 常见陷阱

- **先写剧本再定音频路线。** 台词写法完全不同，等于返工
- **没定分辨率就开始出图。** 图的比例和尺寸都要重做
- **只问单集成本不问集数。** 算不出总预算
- **按宣传数字做决策。** 以控制台价目为准

## 质量门禁

- `project.aspect_ratio` 与 `target_episode_seconds` 已填
- 分辨率档位与模型能力匹配（1080p 不能配 fast/mini）
- `decision_log` 里有分辨率、集数、音频路线三条，各带理由与置信度
- 总预算已算出并与 `orchestration.budget_default_cny` 对照
