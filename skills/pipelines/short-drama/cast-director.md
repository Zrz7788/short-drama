# 实体导演 — 短剧流水线

## 何时使用

剧本之后、出图之前。把剧本里的**人物、场景、道具**抽成统一实体，并分级。

**这一步是整条流水线最省钱的杠杆。** 出图量由它决定，而后面的所有阶段都引用它。

## 前置

| 层 | 资源 | 用途 |
|---|---|---|
| 上游工件 | `script` / `scene_list` | 抽取依据 |
| 表 | `entity` | 落实体与分级 |
| 工具 | `pipeline/stage_entities.py` | 抽取 + 分级 |
| 提示词 | `pipeline/prompts/entities.md` | 交给模型的指令 |
| 定价 | `price_book` | 出图成本预估 |

## 流程

### 1. 三类都要提，别只提人物

| kind | 说明 | 常被漏掉的原因 |
|---|---|---|
| `character` | 人物 | — |
| `location` | 场景/空间 | 觉得"背景随便就行" |
| `prop` | 道具 | **道具常是剧情核心**——一封信、一把钥匙、一张化验单 |

道具漏了的后果：镜头里那个东西每一镜都不一样，而观众恰恰盯着它。

### 2. 分级要克制——它直接换算出图张数

| tier | 出图 | 判据 |
|---|---|---|
| `main` | 定妆照 + 三视图 | **是否需要在多个镜头里保持长得一样** |
| `secondary` | 只出定妆照 | 出场一两次、无特写 |
| `background` | **不出图** | 路人、一次性道具 |

提取出来的实体里，大量是"路人甲""桌上的杯子"。**给它们全出图是纯浪费。**

这一步能把出图量砍掉一半以上，而成本只是分级时多想一秒钟。

### 3. description 必须是"可整段粘贴的文本块"

这一条关系到整个跨镜头一致性机制。

| ❌ 散文 | ✅ 可粘贴的特征块 |
|---|---|
| "成熟知性的职场女性" | "28-32 岁东亚女性，鹅蛋脸，黑色长发及肩，眉形细长，右眼下有一颗小痣，米白色高领针织衫，深灰色西装外套" |

**为什么**：第 6 阶段（提示词）会把 `entity.description` **逐字内联**进每一个
提到该实体的镜头提示词。散文没法逐字内联，一"润色"就变成另一个人。

模型不认识"知性"，它认识"鹅蛋脸、及肩黑发、眼下有痣"。

### 4. 生成与成本预估

```powershell
python pipeline\stage_entities.py --episode-id 1
```

脚本会按分级算出**预计出图张数与金额**并展示。**先看金额再往下走。**

## 常见陷阱

- **把路人判成 main。** 出图成本翻几倍且毫无收益
- **description 写散文。** 第 6 阶段的逐字校验会失败，或者更糟——通过了一个
  没有信息量的描述
- **漏道具。** 剧情核心物件每镜一变
- **漏场景。** 同一间屋子在不同镜头里不一样
- **不看预估金额。** 这一步是唯一能在花钱之前砍量的地方

## 质量门禁

- `entity.kind` 覆盖 `character` 与 `location`（`prop` 可空但要说明为何没有）
- 每个 `entity.role` ∈ {main, secondary, background}
- 每个 `description` 含**具体可画特征**（脸型/发型/服装/材质/颜色），
  不含"气质""感觉""成熟"这类不可画的词
- 出图张数与金额已按 `price_book` 算出并展示
- `background` 级数量合理（不应占多数）
