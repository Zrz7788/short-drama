# 衔接导演 — 短剧流水线

## 何时使用

视频生成之后、拼接之前。抽首尾帧，建立镜头之间的续接关系。

## 前置

| 层 | 资源 | 用途 |
|---|---|---|
| 上游工件 | `takes` | 选中的成片 |
| 表 | `shot.first_frame_path` / `last_frame_path` / `continues_from` | 落帧与续接 |
| 工具 | `pipeline/frames.py` | 抽帧 + 建链 |
| 知识 | `knowledge/02-模型与成本/Seedance提示词与连续性锁定.md` | **冲突一（必读）** |

## ⚠️ 本阶段的设计被推翻过一次

**原来的做法是把相邻镜头默认串起来：后一镜首帧 = 前一镜尾帧。**

**这是错的。** 两个互相独立的来源得出同一结论：

1. 一部已发布的 **110 分钟 Seedance 长片全片禁用起始帧**，理由是上一镜的
   最后一帧**"会拖带它自己的漂移"（drags its own drift）**
2. 一个中文短剧实战技能包把「首尾帧素材」在 SOP 对照表里标为
   **⚠️ 可跳，用 ffmpeg fade 转场代替**

而且逻辑上本来就别扭：**短剧镜头之间大多是硬切**——机位变了、角度变了，
"后一镜从上一镜最后一帧开始"在物理上就不成立。

我们原来把两件事混在了一起：**修单个坏元素**（点修复，对的）和
**承担跨镜头连续性**（这是它警告的用法）。

## 正确做法

| 情形 | 做法 |
|---|---|
| **默认（硬切）** | **断开。** 连续性靠角色资产 + 具名锁 + 状态单调性 |
| 真实延续（同机位同动作、长镜头拆分） | 串联，`continues_from` 指向上一镜 |
| 单个镜头里有坏掉的元素 | 尾帧当**点修复**手段，**不是**连续性方法 |

**所以默认该走 `--no-continuity`。** 串联才是例外，且必须能说明理由。

## 流程

### 1. 抽帧

```powershell
python pipeline\frames.py --episode-id 1 --no-continuity   # 默认：只抽帧，不串联
```

每个镜头都抽出首帧与尾帧——即使不串联，尾帧在点修复和质检时也用得上。

### 2. 只在真实延续时串联

```powershell
python pipeline\frames.py --episode-id 1 --continuity      # 显式要求串联时才用
```

用完要能回答："这两个镜头为什么必须接上？" 答不出来就不该串。

### 3. 自查

```sql
-- 有多少镜头被串联了，以及为什么
SELECT s.seq, s.continues_from, p.seq AS prev_seq
  FROM shot s LEFT JOIN shot p ON p.id = s.continues_from
 WHERE s.episode_id = ? AND s.continues_from IS NOT NULL ORDER BY s.seq;
```

**默认情况下这条查询应该返回空集。** 有结果就要逐条说明理由。

## 常见陷阱

- **习惯性串联。** 这是被两个来源同时警告的做法
- **把分段生成的一集串成一条链。** 硬切之间串起来只会传播漂移
- **不抽尾帧。** 点修复和质检都要用它
- **串联了却说不清为什么。** 那就是习惯性串联
- **以为串联能解决不一致。** 一致性靠资产与锁，不靠帧

## 质量门禁

- 每个 `shot.last_frame_path` 非空且文件存在
- 每个 `shot.first_frame_path` 非空且文件存在
- **默认无 `continues_from`**（有值的镜头必须能说明是真实延续）
- 若确实串联，后一镜 `first_frame_path` == 前一镜 `last_frame_path`

---

## 门禁提醒

本阶段**没有**人工门禁（`human_approval_default: false`）——抽帧是机械的。

但**"要不要串联"是一个判断**，它发生在跑脚本之前。
默认不串；要串就得有理由。
