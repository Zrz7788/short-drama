# 提示词导演 — 短剧流水线

## 何时使用

分镜之后、出首帧图之前。

**本阶段刻意不走 LLM。** 它是确定性拼接——把实体的外观描述、分镜动作、
风格参数按固定模板组装成提示词。这个决定是整条流水线里最重要的一条。

## 前置

| 层 | 资源 | 用途 |
|---|---|---|
| 上游工件 | `shot_list`、`entity_roster` | 组装素材 |
| 表 | `shot.prompt` / `shot.negative_prompt` | 落提示词 |
| 工具 | `pipeline/stage_prompts.py` | **确定性组装，零模型调用** |
| 模板 | `pipeline/prompts/shot_prompt.md` | 分节模板 |
| 知识 | `knowledge/02-模型与成本/Seedance提示词与连续性锁定.md` | **方法依据（必读）** |

## 为什么不用 LLM

> **实体的外观描述块必须逐字复制进每个镜头的提示词。**

一旦让模型"润色"，同一个人在不同镜头里就会被描述成不同的人——
**这正是跨镜头崩脸的起点**。

| | 用 LLM 润色 | 确定性拼接 |
|---|---|---|
| 读起来 | 顺 | 生硬 |
| 跨镜头一致 | **会漂** | 逐字一致 |
| 可复现 | 否 | 是 |
| 成本 | 每镜一次调用 | 零 |

脚本对这一点做了**机械校验**：任何实体的 `description` 没有原样出现在该镜头的
提示词里，**立刻报错**。

**看到那个报错不要绕过它。** 它通常意味着模板被改坏了，或者有人在中间加了
一个"润色"步骤。

## 流程

### 1. 按分节顺序组装

跳过某一节**不会普遍降低质量——它会以某个特定且可预测的方式破坏输出**。
所以每一节都是必要的。

```
GLOBAL STYLE      类型、调色、质感、画幅(9:16)、快门行为，以及绝不能出现的东西
SCENE             一句话：发生了什么、在哪、什么情绪
CHARACTERS        谁，以及**哪张参考图对应哪个角色**
LOCATION          空间与道具，与人物分开写（含糊的场景是跨镜头漂移最常见的原因）
FIRST FRAME       开画时的精确起始位置：谁在哪、朝哪边
Shot 1..N         分镜拆解，每镜写明景别与动作，段间 Hard cut
OPTICS / CAMERA   焦距、机位高度、运动方式，逐镜写明
PHYSICS           布料、烟、头发、液体——任何"按固体运动就会穿帮"的东西
LIGHTING          光从哪来、方向、如何落在脸上
AUDIO             环境音、具体音效，以及绝不能听到的东西
```

**成形提示词共有的形状**：顶部一条视觉规则，底部一条声音规则，中间全是分镜。
`CHARACTERS` 在参考图已承担该工作时可以很短；但 `GLOBAL STYLE`、分镜拆解、
`AUDIO` **无论何时都要保留**。

### 2. 约束写成具名正面锁，不是尾部负面词

**这是一条观念转变。** 我们原来的做法是尾部 `negative_prompt`——那是最弱的写法。

| 锁 | 用在短剧的哪里 |
|---|---|
| `SCREEN DIRECTION` | 对话正反打的轴线。"A 永远在画面左，B 永远在右，绝不互换" |
| `COUNT LOCK` | "画面里正好两人，绝不出现第三个人，镜面/倒影里不能多出人" |
| `FIRST FRAME AND SPATIAL BLOCKING` | 位置用画面 x/y 百分比；反打时谁在哪一侧 |
| `STILLNESS LOCK` | "不发生什么"的清单 |
| `POSITIVE LOCKS` | 结尾用正面措辞重申跨镜头保持不变的东西 |
| `IDENTITY / NO-IP LOCK` | "完全原创、凭空发明的脸"，无商标、无可读文字 |

**替代，而不只是禁止。** 禁止了某样东西就必须给出具体的替代物：
"No blood" 是弱的；"切口边缘泛橙光，火花喷出，身体崩解成灰" 才可执行。

### 3. 状态单调性：最便宜的连续性技巧

**状态只前进，不回退。** 逐镜头把进程写出来：

```
S01 衬衫干整 → S05 肩头湿了一块 → S09 半身湿透 → S13 头发滴水
```

这能阻止模型在下一个镜头**"顺手把你的角色清理干净"**。
而且它**既是叙事，又是连续性**——一句话办两件事。

### 4. 多主体要加一致性负面词

含两个及以上 `subject` 的镜头，负面词里必须有 `人物融合`、`人数变化`。

```powershell
python pipeline\stage_prompts.py --episode-id 1
```

### 5. 机械自查

```sql
SELECT s.seq, e.name FROM shot s
  JOIN shot_entity se ON se.shot_id = s.id
  JOIN entity e ON e.id = se.entity_id
 WHERE s.episode_id = ?
   AND (s.prompt IS NULL OR instr(s.prompt, e.description) = 0);   -- 必须为空
```

## 常见陷阱

- **让模型"润色"提示词。** 崩脸的起点。脚本会拦，不要绕过
- **改完实体描述不重跑本阶段。** 提示词里还是旧描述，一致性链条断了
- **约束只写在尾部负面词里。** 应该写成具名正面锁
- **漏掉 AUDIO 节。** 走原生音频时台词就没地方放
- **禁止了却没给替代物。** 模型会自己发明一个，而且通常更糟
- **多人镜头没加融合负面词。** 会出现"融合脸"

## 质量门禁

- 每个 `shot.prompt` 非空
- **每个镜头关联实体的 `description` 都逐字出现在该镜头的提示词里**
- 每个提示词含 `GLOBAL STYLE`、分镜拆解、`AUDIO` 三节
- 画幅写的是 9:16
- 含多个 subject 的镜头，`negative_prompt` 含 `人物融合`
- 提示词里点名了参考图与角色的对应关系

---

## 门禁提醒

本阶段**没有**人工门禁（`human_approval_default: false`）——它是机械的，
过了校验就是对的，人在这一步看提示词文本收益很低。

**但校验失败必须停下。** 逐字一致性是后面所有镜头的根据。
