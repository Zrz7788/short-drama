# Seedance 提示词契约与连续性锁定

> **出处**：OpenMontage 的 `.agents/skills/seedance-2-5/` 技能包。它自己的声明是：
> 方法提炼自 Higgsfield 团队 2026 年 8 月发布的两份材料——一份 Seedance 2.5 官方提示词
> 指南（十类，每类都跨多次生成测试过），以及一部 **110 分钟 Seedance 长片**的开源制作方法。
> 原文强调"没有逐字复制任何提示词，技术是重述的"。
>
> **置信度**：方法层——**中高**（有明确的第一手来源与测试量）。但这些结论产自
> Higgsfield 的制作环境，不是方舟官方文档；我们尚未在自己的项目里验证过。
> **模型/接口层**——他们的路线表不适用于我们（我们直连方舟），见文末冲突项。

## 一、提示词的分节顺序

**核心主张**：*跳过某一节不会普遍降低质量——它会以某个特定且可预测的方式破坏输出。*
这是我们第 6 阶段"确定性拼接"的更强版本：不只是"别漏掉实体描述"，而是**每一节
缺失都会造成一种可诊断的故障**。

```
GLOBAL STYLE          类型、调色、胶片/数字质感、画幅、快门行为，以及绝不能出现的东西。
                      下面所有内容都必须服从这一节。

SCENE                 一句话讲清：发生了什么、在哪、什么情绪。

CHARACTERS            脸、发型、体型、服装。如果有参考图承担了这件事，
                      就只写"哪张参考图对应哪个角色"。

LOCATION              空间与其中的道具，与人物分开写。
                      **含糊的场景是跨镜头漂移最常见的原因。**

FIRST FRAME AND
BLOCKING              开画时的精确起始位置：谁在哪、朝哪边。
                      在任何运动开始之前就固定下来的东西。

Shot 1: [景别] [一到两句动作]。Hard cut.
Shot 2: [...]。Hard cut.
Shot 3: [...]。
                      **节奏在这里建立。每镜必须写明机位距离与构图**——
                      含糊的转场是序列崩塌最常见的原因。

OPTICS / CAMERA       焦距、机位高度、手持/轨道/摇臂，逐镜写明。

PHYSICS               布料、烟、头发、液体。任何"按固体运动就会穿帮"的东西。

LIGHTING              光从哪来（动机）、方向、如何落在脸上。

AUDIO                 环境音、具体音效，以及绝不能听到的东西。
                      默认写"No music, no discernible dialogue"，除非场景需要。
```

**成形的提示词共有的形状**：**顶部一条视觉规则，底部一条声音规则，中间全是分镜。**

`CHARACTERS` 在参考图已经承担该工作时可以很短；但 **`GLOBAL STYLE`、分镜拆解、
`AUDIO` 三节无论何时都要保留**。

### 类型/年代/光照：写出来，不要留给默认

厂商网页平台上这些是 UI 选择器，光改"类型"就能改变节奏、对比度与机位行为，
而场景描述一字未动。**API 路线没有这些选择器**，所以要把这些意图显式写进
`GLOBAL STYLE` 与 `LIGHTING`：类型、年代、颗粒与色彩响应、光源及角度、情绪基调。

> 原文一句话值得记住：*不写出来，就是"黑色电影"和"只是一片黑"的区别。*

## 二、连续性锁定（跨镜头）

**最重要的一条观念转变**：

> **约束不属于末尾的负面提示词。它们属于「具名块」，且通常用正面措辞陈述"什么保持不变"。**

我们现在的做法是尾部 `negative_prompt`。按这套方法，那是最弱的写法。

| 锁 | 解决什么 |
|---|---|
| `FIRST FRAME AND SPATIAL BLOCKING` | 位置用画面 x/y 百分比表示；并写明反打时的越轴规则——机位过轴后谁在哪一侧，**让他们永不互换** |
| `SCREEN DIRECTION` | 轴线。"海永远在画面右侧，沙丘线永远在左侧，绝不反转" |
| `LENS LOCK` | 每个片段一个焦距，用对角线视场角表示：84° 广角 / 47° 标准 / 29° 人像 / 18° 长焦。加一句"片段中不漂焦" |
| `SINGLE-LENS LOCK` | 全片一个焦距，构图变化来自操作者走动。这才是"纪录片感"的来源 |
| `COUNT LOCK` | "正好四个，绝不五个；背景里没有替身；镜面或倒影里不能多出一个人" |
| `STILLNESS LOCK` | "不发生什么"的清单：没有人站起来、没有人拥抱、没有手离开毯子 |
| `POSITIVE LOCKS` | 结尾块，用正面措辞重申跨镜头保持不变的东西 |
| `IDENTITY / NO-IP LOCK` | "完全原创、凭空发明的脸"。无商标、无可读文字、无可识别的旋律 |

### 状态单调性（state monotonicity）——最便宜的连续性技巧

**状态只前进，不回退。** 湿了只能更湿。饼干只会变小——完整的、咬了一口的、
两半的、吃完的——绝不会变回来。逐镜头把进程写出来，能阻止模型在下一个镜头
**"顺手把你的角色清理干净"**。

> 对短剧的价值极高：衣服越穿越乱、伤口越来越重、雨越下越大、
> 手中的信越攥越皱。这既是叙事，又是连续性。

### 一个动作一种语法

某个动作重复出现时，**定义一种执行方式并禁止其余**，然后收口：
"全片恰好五次挥剑，各自带时间戳"。慢动作同理——只允许名单里那几个时刻，
其余地方禁止。

### 事件轨迹

环境元素**写成带时间戳的事件列表**，而不是"质感"：每一道浪带秒数与浪花高度
（占画面百分比），间隔不规则。适用于海、风、雨、车流、人群。

### 替代，而不只是禁止

**禁止了某样东西，就必须给出具体的替代物。**

- 弱："no blood"
- 可执行："切口边缘泛橙光，火花喷出，身体崩解成灰"

## 三、角色资产法（片子在这里就赢或输了）

> 原话：**"The piece is won or lost here, before any video generates."**

### 角色表（character sheet）：三张图，脸只出现在一张上

| 图 | 内容 |
|---|---|
| 1 | 全身正面，**把脸去掉** |
| 2 | 全身背面 |
| 3 | 3/4 特写，**带脸**，做两个版本：微笑 与 中性 |

**为什么全身图要去掉脸**：远景里脸又小又糊，**模型会复制那个糊**。
如果整套里唯一清晰的脸就是那张特写，**它就会用那张**。

**为什么必须有微笑版**：没有微笑版本，**模型会自己发明牙齿**。

### 一个状态一个资产

"干净的夹克 / 湿透的 / 带血的"应该**拆成三个独立资产**，而不是写在提示词里描述。
原话：**"拆分比争论便宜。"**

### 10 次法则

**接受一个资产之前，用不同姿势和光照生成 10 次。它必须在 10 次里都认得出来。**

这是可以直接搬进我们"定妆照门禁"的验收标准——比"看着还行"强得多。

### 场景：不要生成正面静止图

**生成一段"空场景 + 镜头缓慢移动"的视频**，再从这段视频里推导房间的其他面。

> 原话：**"静止图给你一堵墙，缓慢移动的镜头给你几何结构。"**

## 四、声音是条件句，不是资产

为角色写**一句话**（口音、语速、说话方式），然后**每次该角色开口都逐字粘贴，
一个字都不改**。改写措辞会扩大采样范围，让声音不稳定。

口音要写成**"嘴在做什么"**，而不是"说话人来自哪里"：
`th 变成 f 和 v、h 脱落、喉塞音 t、-ing 变成 -in'`。

**音频轨必须分开。绝不要把配音和音乐放进同一个参考片段。**

> 这跟我们"实体描述必须逐字内联"是**同一条规则在声音上的翻版**。
> 两处独立得出同一结论，说明这条规则是本质的，不是巧合。

## 五、模型做不到的三件事

| 做不到 | 变通 |
|---|---|
| **唱歌** | 预先录好，切成 12 秒一段，每段标注 `THE TRACK THEY ARE PERFORMING`（说明这段音频在场景中的**角色**）。写"audio guide, for sync only"虽然技术上准确，但**产出为零** |
| **持续的身体接触** | 打斗、两个人持续贴身。用手机拍参考视频当动作参考传进去，比迭代二十次便宜 |
| **多角色场景** | **最难的一类。** 一个镜头里的脸越多，每张脸需要的参考素材就越多，否则到第三四个镜头就漂成一张通用脸 |

> **对短剧的直接冲击**：短剧有大量多人对话场景，而这正是模型最弱的地方。
> 分镜时应主动避免"三四人同框"，改成**正反打 + 过肩**，一次最多两张脸。

## 六、迭代纪律（把成本框住）

- **生成任何东西之前先把资产锁死。** 原话：**"模型没有记忆：每次都要重新描述一切。"**
- **每次只改一样东西**，否则你不知道是哪一处修好的
- **失败 10-15 次后，简化或拆分场景，而不是改措辞**
- 在路线支持的最低分辨率上探索，只重跑有效的
- 留一份日志：版本、改了什么、结论
- **判断整条片段，绝不要只看单帧。** 原话：**"一张好静帧可能来自一段第 9 秒就崩掉的生成。"**
- **切点落在运动上，绝不落在静止姿势上**

### 纠错，而不是重生成

单个元素错了，去**编辑**它，并说清什么变、什么不变：

```
Around the 2-second mark, change only [X] from [before] to [after].
Keep the characters, movement, camera, lighting, composition and timing unchanged.
```

修补好的那一帧也可以当起始图，去做一段短的替换片段。
但原文提醒了一个张力，见下。

## 七、⚠️ 两处与我们现有设计的冲突

### 冲突一：用「上一镜尾帧」做连续性，可能是在引入漂移

我们第 9 阶段（`frames.py`）默认把相邻镜头串起来：
**后一镜首帧 = 前一镜尾帧**。

而原文说：

> 一部已发布的 110 分钟 Seedance 长片**全片禁止使用起始帧**，
> 所以连续性由**资产**承担，而不是由上一个 take 的最后一帧承担——
> **后者会拖带它自己的漂移（drags its own drift）。**
> 把起始帧修补当作**点修复**，不要当作连续性方法。

**这是一个直接的、有分量的反证。** 我们拿"上一镜尾帧"同时干了两件事：
① 修复单个错误（点修复，这是对的）② 承担跨镜头连续性（这是它警告的用法）。

而且逻辑上本来就别扭：**短剧镜头之间大多是硬切**——机位变了、角度变了，
那么"后一镜从上一镜的最后一帧开始"在物理上就不成立。

**建议的修正**（待你确认）：
- **默认断开** `continues_from`，连续性靠**角色资产 + 具名锁 + 状态单调性**承担
- 只在**真实延续**时串联：同一机位、同一动作、明确要接上的情况（长镜头拆分）
- 保留"上一镜尾帧"作为**点修复**手段，用于修单个镜头里坏掉的元素

### 冲突二：1080p 到底能不能通过 API 出

那份技能包说：

> 上述支持的路线只暴露 480p 和 720p。模型在**厂商自己的网页平台**上原生生成 1080p，
> 而那**不是 OpenMontage 的路线**。如果厂商博客提到 1080p 或 4K，
> 先搞清楚它说的是哪个界面，再在管线里承诺。

但我们的 `.dsh/skills/ark-seedance` 写的是：`doubao-seedance-2-5-260628`
支持 `480p/720p/1080p/4k`，且单价 ¥1.45/秒 来自你在控制台看到的价目。

**两者冲突。** 可能的解释有三种：
1. 他们说的是 fal/Runway/ComfyUI 路线，方舟直连不受此限（**最可能**）
2. 方舟也限制，我们控制台看到的是网页平台的价目
3 他们的信息已过时

**必须核实**，因为它是我们整个 Draft 策略的支点：**样片 480P、成片 1080P**——
如果成片出不了 1080P，这套三段式就要重新设计。

**核实方法**（插上 key 后的第一件事）：用 `--resolution 1080p` 发一个最小的
视频任务，看是否返回 400。`ark.py` 已经把原始响应落盘到 `.tools/ark-debug/`。

## 八、可以直接进我们流程清单的改动

| 我们的现状 | 应该改成 |
|---|---|
| 尾部 `negative_prompt` 承载约束 | **具名正面锁块**（`SCREEN DIRECTION`、`COUNT LOCK`、`STILLNESS LOCK`、`POSITIVE LOCKS`） |
| 三视图 = front / side / back | **角色表 = 全身正面(去脸) / 全身背面 / 3/4 特写(带脸，微笑+中性两版)** |
| 场景定妆照 = 一张静止图 | **空场景 + 缓慢移动镜头的短视频**，从它推导其他墙面 |
| 定妆照门禁靠"看着还行" | **10 次法则**：10 次不同姿势光照下都认得出 |
| `continues_from` 默认串联相邻镜 | **默认断开**，连续性靠资产与锁（见冲突一） |
| 提示词无固定分节 | **按十节顺序**，`GLOBAL STYLE` / 分镜拆解 / `AUDIO` 三节必留 |
| 角色状态由各镜自由描述 | **状态单调性**：只前进不回退，逐镜写出进程 |
