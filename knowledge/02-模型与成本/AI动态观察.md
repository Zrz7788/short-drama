### ⭐⭐ LTX-2.5 的「原生多镜头生成」可能改变我们的架构

> **原生多镜头生成（单次推理生成多个连续镜头，保持角色/光线/风格一致性）**

**我们整条流水线是"逐镜生成再拼接"**——`shot` 表、`first_frame_path`/`last_frame_path`、
`frames.py` 的续接、`stage_video.py` 的逐镜抽卡、最后 `assemble.py` 拼。
**而 LTX-2.5 一次推理就给你多个一致的镜头。**

**这是一个根本性的架构分岔**，值得认真评估，而不是当成"又一个模型"。

其它要点：
- **扩散视频解码器替代 VAE** —— 面部细节、纹理、**文字清晰度**显著提升（文字清晰度正是我们的痛点）
- **4K HDR 3840×2176**
- **10 秒片段在 NVIDIA 高端 GPU 上约 6–8 秒生成**
- HF 下载量 **1,630,000/月**，❤️ 6,050

### 对我们的现实约束

**这些都是本地/自托管的开源模型，而我们走的是火山方舟 API。** 两条路线：
- **继续走 API**（种子/成本可控，但受模型能力限制）
- **自托管**（LTX-2.5 22B / Kandinsky Lite 3B，需要 GPU 与运维）

**Kandinsky 6.0 Lite 只有 3B、MIT 授权、"可在消费级 GPU 运行"** ——
这是自托管路线里门槛最低的一个。

## 三、⭐ 决策模型 / Agent 路由：和我们刚学的技能路由直接相关

| 日期 | 条目 | 要点 |
|---|---|---|
| 2026-10-10 | **Cloudflare Clef** | 27B、**零输出 token**、返回**校准概率**、单次决策 209ms、BFCL case-exact **98.5%** |
| 2026-10-06 | Cloudflare 首个自研开源决策模型 | **38ms 结构化决策，重新定义 Agent 路由范式** |
| 2026-09-29 | **CLM-8B** | 用**对比学习代替文本生成**，智能体决策速度提升 **9×** |

**Clef 的定位**（原文）：
> 传统智能体工作流用「大模型生成 JSON → 解析 → 重试」，延迟 100ms+ 且出错率高；
> 专用小分类器无法泛化。Clef 提出「决策模型」新范式：输入状态+问题模式（schema），
> **一次前向传播直接输出每个选项的校准概率，完全无需生成文字**。

**⭐ 这正好呼应我们刚学的技能路由三种误选**（`技能路由的三种误选.md`）：
那个 bug 的根因之一就是**拿散文描述做子串匹配**。
**Clef 的思路是"不做文本匹配，直接对选项出概率"。**

**而且我们的第 2/5/6 阶段全靠"让模型生成 JSON → 解析 → 校验 → 重试"** ——
正是 Clef 说要取代的那套。**值得关注，但不急着改**（它要自托管 27B）。
