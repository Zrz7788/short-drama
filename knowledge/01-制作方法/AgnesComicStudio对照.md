# Agnes Comic Studio 对照（同类项目的另一种划分）

> **出处**：`github.com/Lusensec/agnes-comic-studio`（提交 `97e5d58`，2026-10-05）
> Python / 43 个文件 / 约 2,369 行 / 无协议声明
>
> **它是什么**：漫剧 / 短视频创作 Skill 套件，基于 Agnes AI Flash 系列模型。
> 「一个故事概念 → 剧本 → 角色三视图/背景/道具/分镜图 → 短视频 →
> TTS 配音 + 字幕 + 合成，全自动化流水线」。
>
> **和我们的关系**：**做的是同一件事**，但**划分方式和取舍都不同**。
> 它小得多（2,369 行 vs 我们的十几个阶段脚本），是个很好的对照样本。

---

## 一、⭐ 它的 SKILL 划分（6 个）vs 我们的阶段划分（10 个）

| 它的子 Skill | 核心能力 | 对应模型 |
|---|---|---|
| `agnes-flash-suite` | 基础能力（生图/生视频/对话） | 全系列 |
| `script-writer` | 剧本 + 角色设定 + 分镜脚本 + **模板预设** | agnes-3.0-flash |
| `storyboard-gen` | 三视图 / 背景 / 道具 / 分镜 + URL 存储 | agnes-image-2.5-flash |
| `video-composer` | 图生视频（reference）+ 429/503 退避 + **可选 TTS 音频参考（对白嘴型同步）** | agnes-video-2.5-flash |
| `post-production` | TTS 配音（场景对齐）+ 字幕 + BGM + 最终合成 | edge-tts + ffmpeg |
| `asset-manager` | 资产追踪 / 项目文件夹管理 | 本地 |

**对照我们的**：spec → script → cast → art(characters/scenes/props) →
storyboard → prompts → keyframes → motion(draft/direct/final) → continuity → assemble。

**差别**：
- 它**没有独立的"实体提取"和"提示词组装"阶段** —— 剧本 JSON 直接带角色和分镜，
  生图脚本自己拼提示词
- 它**把 TTS 放在视频之前**（`Step 2.5`），理由是
  **"推荐先出 TTS，视频才能做嘴型同步"** —— 而我们选的是原生音频路线
- 它**没有 continuity 阶段**（没有跨镜一致性校验）

## 二、⭐⭐ 一条直接指出我们代码隐患的准则

> **⚠️ Agent 行为准则（每步必须确认）**
>
> **每个 Step 执行完毕后，Agent 必须 STOP 并向用户确认，不得自动跳到下一步。**
>
> **脚本末尾打印的「下一步」是给用户看的操作提示，
> Agent 不应忽略它直接链式执行。**

### ⚠️ 我们正是这么写的

`pipeline/run.py` 的输出结尾就是：

```
阶段 cast（有人工门禁）
  产出：entity_roster
  命令：python ...\stage_entities.py --episode-id 1 --db ...

存档 #7 已开（in_progress）——中断也能从这里接上。

阶段 cast 已完成，**在等你批准**。
```

**我们打印了一行"命令：…"**。**一个 agent 看到这行，完全可能直接执行它**——
而那正好绕过人工门禁。

**这是真实的隐患，不是理论风险**：我自己在会话里就多次直接复制那行命令去跑。

**应该改**：
1. 输出里**明确标注"这行是给人看的，Agent 不得据此自动执行"**
2. 或者**只对无门禁的阶段打印命令**，有门禁的阶段只打印"等你批准"

## 三、它的其它可取之处

### 3.1 速率限制的退出码约定

> **速率限制防范** — 自动 sleep + 429/503 退避，**队列满时快速失败（exit 3）**，
> **重跑自动跳过已完成片段（幂等）**

**`exit 3` 是一个专门约定**：不是错误，是"现在做不了，稍后再来"。
编排层可以据此**等待重试**而不是**报警**。

**对照我们**：`stage_video.py` 的失败一律返回 1，编排层分不清
"参数错了"和"服务排队满了"。

### 3.2 平台预设

| 名称 | 用途 | 方向 | 时长 | 风格 |
|---|---|---|---|---|
| `douyin` | 抖音竖屏短剧 | 9:16 | 5s | 动画 |
| `bilibili` | B站横屏动画 | 16:9 | 8s | 二次元 |
| `xhs` | 小红书图文漫 | 3:4 | 4s | 二次元 |
| `weibo` | 朋友圈短动画 | 1:1 | 4s | 动画 |

**我们只有 9:16 / 16:9 两种画幅，没有"平台"这一层概念。**
把"平台"作为一等公民（一键配置方向+时长+风格+尺寸）比散落的参数好。

### 3.3 资产表设计（比我们的简单得多）

```sql
CREATE TABLE IF NOT EXISTS assets (
    id, project, asset_type,   -- script | image | video | reference
    filename, filepath, description,
    created_at, updated_at,
    tags                       -- 逗号分隔标签
);
```

**对照我们的 `entity` + `entity_ref` + `image_generation` + `generation` + `cost_ledger`**：
我们的表结构能表达"同一实体的多个视角及其指纹"，**信息量更大**；
但它的 **`tags`（用于搜索/复用）** 是我们没有的。

**跨项目复用素材**需要我们按 `project_id` 隔离，而它靠 `project` 字段 + `tags` 搜索。

### 3.4 Windows GBK 控制台自动切 UTF-8

> 中文 Windows 默认 GBK 控制台，**脚本已内置 stdout/stderr 自动切 UTF-8**，
> 直接 `python xxx.py` 即可，无需手动 `chcp 65001`

**我们踩过这个坑**（PowerShell 里中文乱码、内联脚本引号被吃）。
**可以照抄这个做法**：脚本开头自动重配 stdout 编码。

## 四、⚠️ 它做错的地方（我们已修正）

### 4.1 它用「角色三视图」

> `storyboard-gen`（角色**三视图**/背景/道具/分镜图）

**这正是我们已证伪的**：官方明确说多视角参考素材会让模型看到多个主体 →
**"双胞胎问题"**。三个独立来源一致（拾音人直接禁用、OpenMontage「脸只放一张」、
Jarvis 实测「用面部特写＋全身照，不用三视图」）。

**我们的方案**：人物资产 = `headshot`（只脸）+ `fullbody`，**先出全身再出大头照**（i2i 引用）。

### 4.2 它把 TTS 放在视频之前

它是 `Step 2.5: gen-tts` → `Step 3: video-composer`（带音频参考做嘴型）。
**这条路是对的**（先有音频才能对嘴型），但它**依赖外部 TTS**。

**我们选的是原生音频路线**（Seedance 原生生成），并在知识库里记过：
「原生对白做不出来就改镜头设计，不走后期配音」。**两条路各有代价。**
