# 配音与口型架构

> **这是一条架构级决定**：它同时决定台词怎么写、分镜怎么拆、后期做什么。
> 先说结论，再说依据。

## 结论

**仿真人竖屏短剧走模型原生音频。** 台词直接写进提示词，由 Seedance 2.x
在生成视频的同一轮里产出语音。

理由只有一条，但它是决定性的：**它没有"对口"这个环节。**

## ffmpeg 的真实职责边界

先把一个常见误解澄清掉，因为它是很多人卡住的地方：

> **ffmpeg 不做口型对齐。它只做时间轴与混音。**

| 需求 | 谁做 |
|---|---|
| 把配音按时间码铺到时间轴上（`adelay`） | ffmpeg |
| 多轨混合（`amix`）、压低 BGM、响度标准化 | ffmpeg |
| **让嘴型对上语音** | **模型**（原生音频，或 reference_audio 驱动） |

所以"用 ffmpeg 配音难对口"这个前提**本身是错的**——那是拿螺丝刀拧螺母。
如果你在用 ffmpeg 硬对口型，问题不在 ffmpeg 用得不好，而在于**选错了路线**。

## 三条路线

| 路线 | 口型怎么来 | 可控性 | 成本 | 适用 |
|---|---|---|---|---|
| **① 模型原生音频** | **天然对齐，无对口环节** | 低 | 已含在视频单价里 | **仿真人写实短剧** |
| ② `reference_audio` 驱动 | 你给配音，模型让口型对上 | 中 | 视频价 + 配音成本 | 要特定音色 |
| ③ 外部 TTS + 后期对口型 | Wav2Lip / MuseTalk / SadTalker | 高 | 视频价 + 配音 + 对口型算力 | 换语言、配音替换 |

### ① 模型原生音频

Seedance 2.x 在一次输出里同时产出画面与声音，读取角色的嘴型动作来匹配语音节奏。

**好处**：省掉整个后期音频环节，口型天然一致。
**代价**：**失去对配音的精细控制**——换声线、改一句台词重配都难。
**能力范围**（第三方资料声称，未核实）：多语言、方言、唱歌、从参考视频克隆音色。

### ③ 外部 TTS + 后期对口型

这是 **OpenMontage 的路子**：先出 TTS 音频，再用 `lip_sync`（Wav2Lip）或
`talking_head`（SadTalker / MuseTalk）让口型对上。

**注意 Wav2Lip 是 2020 年的模型**，下巴区域容易糊，且需要额外算力。

### ② 折中：reference_audio

用外部 TTS 生成配音，把它作为音频参考传给 Seedance，模型让口型对上。
**兼顾可控与对齐**，是想指定音色时的首选。

## 主流实践：两条路都真实存在，按内容类型分

| 内容类型 | 做法 | 实例 |
|---|---|---|
| **漫剧 / 动画风** | **外部 TTS + ffmpeg 混音** | `ai-mandrama-skills`（Dreamina + **edge-tts** + ffmpeg） |
| **仿真人 / 写实** | **模型原生音频** | 即梦+可灵+豆包+剪映 全链路教程（标注"原生配音"） |

**为什么漫剧走外部 TTS**：漫剧口型本来就不是真人级别，观众不苛求。
换来的是完全可控——逐句调声线、调情绪。

**为什么仿真人走原生音频**：写实画面的口型错位立刻被看出来，
而原生音频**根本不存在错位**。

## 这个决定对上游的影响

### 对台词写法

| 走原生音频 | 走外部 TTS |
|---|---|
| 台词直接写进提示词 | 台词要单独整理成配音表，逐句标声线与情绪 |
| **标点参与节奏控制**（见下） | 声线/情绪由 TTS 参数控制 |
| 台词要短——模型一次念不完会含糊 | 时长由音频决定，可以稍长 |

**标点作为技术参数**（不是文学修辞）：

| 标点 | 效果 |
|---|---|
| 叹号 | 加强语气 |
| 省略号 | 制造悬念断点 |
| 破折号 | 拉长元音 |
| 逗号 | 自然停顿 |

### 对分镜

**多人同框不做长对话**——那是模型最弱的地方，而且原生音频在多角色场景下
更容易串味。改用正反打与过肩镜头。

## 如果走外部 TTS：可用的具体做法

来自 `skills/techniques/edge-tts-chinese-roleplay`（MIT，已装）：

**4 类角色声线**（微软 edge-tts，免费）：

| 角色 | Voice |
|---|---|
| 阳光男主 | `zh-CN-YunxiNeural` |
| 反派 / 怒吼 | `zh-CN-YunjianNeural` |
| 萌系配角 | `zh-CN-YunxiaNeural` |
| 温柔旁白 / 系统 | `zh-CN-XiaoxiaoNeural` |

**6 类情绪 rate / pitch 表**：

| 情绪 | rate | pitch |
|---|---|---|
| 紧张惊恐 | +25% | +10Hz |
| 阳光调侃 | +8% | +3Hz |
| 沉重 OS | -5% | -3Hz |
| **霸气一字定海** | **-30%** | **-5Hz** |
| 系统机械感 | -15% | -2Hz |
| 谄媚拔尖 | +20% | +10Hz |

**混音命令**（多段 mp3 按时间码铺开 + 多轨混合）：

```bash
ffmpeg -y -i input_video.mp4 -i seg_01.mp3 ... -i bgm.wav \
  -filter_complex "
[1:a]aresample=44100,adelay=500|500,volume=14[t1];
...
[16:a]aresample=44100,adelay=4000|4000,volume=0.18[bgm];
[t1]...[t15][bgm]amix=inputs=16:dropout_transition=0[aout]" \
  -map 0:v -map "[aout]" -c:v copy -c:a aac -b:a 192k -shortest output.mp4
```

三个非直观的参数（实测踩出来的）：

- **`volume=14`** —— 补 `amix` 默认按 1/N 的衰减（16 段输入就衰减 16 倍）
- **`volume=0.18`** —— BGM 压到 18%，不盖配音
- **不要加 `normalize=0`** —— 老版 ffmpeg 不识别（我们是 n9.0，没事）

## 常见陷阱

- **用 ffmpeg 对口型。** 选错了工具，它只做时间轴与混音
- **先写台词再定音频路线。** 两条路的台词写法完全不同，等于返工
- **以为原生音频可以后期换声线。** 换不了，要重生成视频（¥5.8 一次）
- **多角色同框靠原生音频。** 模型最弱的场景 + 音频串味
- **混音忘了补 `volume`。** 多段一起混会整体变轻
