# 分镜表字段规范

分镜表是**生产工单**——它同时喂给视频生成脚本和数据库。字段口径以 `db/schema.sql` 的 `shot` 表为准，
本页只解释每个字段**为什么存在**和**怎么写**。

## 与数据库的对应

| 分镜表列 | `shot` 表字段 | 说明 |
|---|---|---|
| 镜号 | `seq` | 集内序号，从 1 开始 |
| 时长(秒) | `duration_s` | 4–15，实际填 4 或 5 |
| 景别 | `shot_size` | 特写/近景/中景/全景 |
| 运镜 | `camera_move` | 推/拉/摇/移/跟，写进 prompt |
| 画面描述 | `description` | **人看的**，给审片用 |
| 提示词 | `prompt` | **模型看的**，给生成用 |
| 负面词 | `negative_prompt` | 排除项 |
| 台词 | `dialogue` | 用于配音与口型 |
| 音效 | `sfx` | 环境音/拟音 |
| 角色 | `char_id` | 关联 `character` 表，锁定一致性 |
| 策略 | `strategy` | `draft` 或 `direct`，见抽卡策略 |
| 计划抽卡 | `draws_planned` | 这个镜头打算抽几次 |
| 状态 | `status` | pending/approved/rejected/final |

## 关键区分：`description` 和 `prompt` 不是一回事

这是最容易搞混的地方，也是仿真人短剧质量的分水岭。

- **`description`** 是给**导演/审片人**看的："女主在雨里回头，眼神从怀疑变成确认"
- **`prompt`** 是给**模型**看的：必须写清镜头、景别、光线、动作幅度、运镜、风格关键词

模型不知道"怀疑变成确认"是什么样。prompt 必须把它翻译成可见的东西：
面部微表情、眼神方向、镜头距离、光照条件。

**建议**：`prompt` 里显式写明景别和运镜，哪怕 `shot_size` / `camera_move` 字段已经有了——
因为那两列是给人做统计用的，不会被自动拼进请求。

## 角色一致性字段

`shot.char_id` 关联到 `character` 表，而 `character` 表持有：`ref_image_path`（定妆参考图）、
`seed`（固化种子）、`appearance`（外貌设定）。

**出片时这些必须一起进请求**，否则第 3 集主角就会换脸。详见 `角色一致性SOP.md`。

## 策略与抽卡

`strategy` 和 `draws_planned` 让**每个镜头单独决策**，而不是全片一刀切。
正脸对手戏抽 4–6 次、空镜直出 1 次，这是省钱的真正来源。详见 `抽卡策略与Draft模式.md`。

## 生成记录不在分镜表里

分镜表的 `draws_planned` 是**计划**；实际每次调用记录在 `generation` 表（一次 API 调用 = 一条），
包含真实模型 ID、分辨率、是否 draft、任务 ID、状态、实际花费。**计划与实际的差异只能在 `generation` 里看出来**，
这也是复盘改进抽卡命中率的唯一数据来源。

## 填表纪律

1. **一次只填一集**，填完立刻入库，不要用 Excel 当长期真源——分镜会反复改，Excel 没有版本追溯
2. **`prompt` 不许留空**。留空的镜头到最后一定会返工
3. 时长字段填真实的秒数，不要按 5 秒凑整（2.x 支持 4–15 秒，凑整是白送钱）
