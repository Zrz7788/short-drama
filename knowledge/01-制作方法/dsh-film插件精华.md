## 一、⭐ 五条我们完全没有的工程纪律

### 1. 「规则强度」三分法 —— 一个治理模型

它把**所有规则**分成三档，**档位决定"违反时怎么办"**：

| 档 | 内容 | 违反时 |
|---|---|---|
| **可核查的** | id、引用、**被追踪的物件**、引号里的矛盾 | **修正或报告；这些会阻断交接** |
| **工艺默认值** | craft.md 里的技法 | 遵循，除非作者意图另有说明；**偏离时说明理由** |
| **品味** | 结局基调、钩子类型、视角、风格 | **作者决定；绝不用它阻断** |

**我方现状**：我们的门禁只有"硬/软"两级，而且**没有"这是作者的品味，不该阻断"这一档**。
结果是我们的校验容易越界——把品味问题当成错误拒收。

### 2. 乐观并发 —— 改稿的完整协议

```
1. 读目标，**保留它的 revision**
2. story_apply_ops { expectedRevision, operations, operationId, dryRun: true }
   → 检查 changedIds 和 preview **是否恰好覆盖预期范围**
3. 去掉 dryRun，**同样的 operations / revision / operationId** 再发一次
4. 报告存了什么：changed ids 与新的 revision
```

**冲突处理（原文）**：
> `STORY_CONFLICT`：别人先改了。**重读，只在新闻本上重建你的改动；
> 绝不把一次失败的局部编辑变成整篇重写。**

> 响应丢失：**用同一个 operationId 重发**；回 `changed: false` 说明已经生效过了。

**⭐ 另一种"规则强度"**：`operationId` 保证**幂等**，`expectedRevision` 保证**不覆盖别人的改动**。
我方 `stage_script.py` 是"直接写库"，没有并发保护。

### 3. 覆盖率追踪 —— 防止"没读完就下结论"

> `coverage` 说明你**实际读了多少**；**要对全稿下判断，必须从 offset 0
> 按顺序读到底，直到 `coverage.truncated` 为 false。**

**我方现状**：没有这个概念。模型读了一段就下结论，我们无法知道。

### 4. ⭐ 本地时钟铁律（写视频提示词时）

> **每个视频片段必须用从 0 秒开始的本地时钟**，后段镜头也是。
> 全局起止时间**只是剪辑或片段的元数据，绝不写进模型的动作/音频时间轴**。
>
> 换算示例：全局 31–60 秒的片段属于一个 30 秒镜头 → **用本地 0–30**；
> 全局第 31–35 拍 → **本地 0–4**。终点用**节点的实际时长**，
> 绝不用全局终点或示例时长。

> 时长已知时，**从 0 连续覆盖到该节点时长，不留空、不超出**；不允许负时间、
> 延迟开始或超出。**不要凭空发明或延长时长。**

**我方现状**：没有这条。我们的 `shot` 是片段级的，但如果将来做长镜头拼接，
**这就是必须的规则**。

### 5. 故事影响分析 —— 已有产出是历史，不是待办清单

> `story_impact`：**在提议下游更新之前先读它。**
> **已有的产出是历史，不是待办清单；改动它们需要用户的请求。**

**我方现状**：没有。改了剧本之后，下游已出的图/视频会不一致——我们没有任何机制提示这件事。

## 二、写作技法（craft.md）—— 每条都带「自检」和「不适用」

**这个结构本身值得学**：每条技法都给出「**怎么自检**」和「**什么情况下不适用**」。

### 场景
- **说出赌注是什么**（信任/钱/秘密/安全/尊严），以及它**在开头和结尾是升是降**。
  **两头一样 → 这场只传递信息 → 删掉，或把信息搬进一场有冲突的戏。**
- 一个 beat = 一个动作加它的反应。行为改变时新 beat 开始（试探 → 逼问 → 退让）。
  **同一种策略换个说法 = 重复的 beat —— 弱场景的第一个征兆。**
- **进得晚，出得早**：铺垫之后才开始，冲突完全解决之前就切走。
- 选**有压力的地方**，不是方便的地方。**"在葬礼招待会上低语的忏悔，比在沙发上贵得多。"**
- **自检**：删掉这场，后面哪件事讲不通？**都讲得通，就合并或删掉。**
- **不适用**：有意的停顿、仪式或过渡场——它们管节奏，不管价值翻转。

### 动作行
- 现在时、看得见听得见的东西、**按观众遇到的顺序**。**一个视觉想法一段；新段落常读作新镜头。**
- 精确名词与动词：不是「很贵的衣服」而是「**熨得发亮的藏青西装**」；
  不是「走过去」而是「**侧身挤过两张桌子**」。
- 内在状态变成行为或声音：
  - 弱：他很紧张。
  - **强：他第三次合上打火机盖，没点。**
- 小物理动作承载整场戏：**吃到一半的面、折了两次的车票、没拆的快递**。
- **自检**：遮住对白只看动作，**看得出这场谁占上风吗？**

### 对白
- **写之前先规划每个说话人**：他嘴上说要什么 / 实际要什么 / 为什么不能说。
  **两者一致时，这段没有潜台词——只在有意为之的时候保留。**
- 每个回合都要做事（试探/挡回/交换/佯退）。
  **两人轮流给观众递事实，那是审问，不是戏。**
- **回答那个没被问的问题**：
  - 弱：A：你昨晚去哪了？ B：去加班了，项目周五上线。
  - **强：A：你昨晚去哪了？ B：（把外卖袋放到桌上）趁热吃。**
- 声音在**句式**上不同（长短句、反问或陈述）、词汇、受压时往哪退、拒绝谈什么。
- 砍掉问候、直呼其名、以及**确认刚刚已经画出来的东西的台词**。
- 长篇独白需要有长的理由（被逼到墙角/仪式/越编越大的谎）**和一个崩掉的地方**。
- **自检**：遮住署名，**还分得清谁在说吗？分不清就改句式和回避方式，不要靠加口头禅。**
- **不适用**：喜剧的重复梗、人物口癖、方言——重复是设计时，**第二次要带来新的意思**。

### 因果与升级
- 场与场之间用「**因为…所以…**」或「**但是…**」连接，**绝不用「然后」**。
  **只靠"然后"相邻的两场戏，缺一个后果。**
- 升级靠**改变风险的东西**（权力/信息/关系/暴露/资源/时间），**不是靠把同样的东西喊得更响**。
- 分清每一次转折是什么：**揭示**改变观众的理解 / **反转**改变行动方向 / **回收**花掉前面种下的东西。
- **短片通常只需要一个中心转折，不需要三幕。**
- **自检**：用一句「因为…所以…」串起全部场次，**串不上的那一环就是缺口**。

### 道具、伏笔与回收
- **可见地、早地种下回收需要的东西。回收每一个伏笔，否则砍掉它。**
- 承载意义的物件**通过某人的动作易手，每次都在一个转折点上**。
  > 《桃花扇》里的扇子每一步都意味着新东西——题诗的爱情信物、溅血的扇子、
  > 血迹被画成桃花、扇子被撕碎——**每一次变化都是某人的动作**。
- **追踪东西在哪、谁拿着；缺一次拿取或交接是连续性问题，不是解释问题。**
- **自检**：**这件道具哪一次露面删掉也不影响剧情？删掉那一次。**

## 三、短形式与竖屏短剧（short-form.md）

- **一个压力、一个人、一个中心转折**，**结尾画面回答开头画面**。
- **地点少、人少**：下游每一个地点和人都会变成一个设计、一份参考表**和生成成本**。
- **用行为结尾，不用陈述。** 不是「两人和解了」，而是「**她把伞往他那边偏了一点**」。
  模糊结局可以；**把你想要的意图写进回复里，不要写进剧本里**。

### 竖屏短剧（最贴我们）

- **第一拍就是钩子**：一个决定、一个危险、或一个需要回答的错——**在头几行，不是铺垫之后**。
- **每集交付一部分承诺（一个本地结果），然后留下一个具体的决定、危险或问题。**
- **让代价跨集累积**：**"如果每个代价都在本集内偿还，就没有东西积累。"**
- **变化结局形状**：揭示/反转/决定/安静的意义改变都行；
  **"同一种悬念形状每次都用会磨损。"**
- **每集末尾写它的交接状态**（谁知道什么、谁拿着什么、什么变了），**下一集从这里开始**。
- **竖屏偏好脸、手、物件的中近景**；**需要宽地理才能读懂的动作很难交付**。
- **类型公式（打脸、逆袭、爽点节奏）是作者可以要求的选项，不是默认。**

### 时长估算
- **靠"在脑子里演一遍"估**：台词按语速、动作按真实长度、停顿算进去。
- 仅供规划：**普通话对白约每秒 4 字**（不含标点）；**动作没有字率**。
- **在计时/排练/渲染镜头量出来之前，一直说"估计"。**

### 为生成视频写作
- 一个生成镜头**几秒到约 15 秒**。**需要 40 秒的演讲需要好几个镜头。**
- **一个说话块只有一个说话人的话轮**，并与它的人绑定 →
  它会变成一条口语行，镜头提示词可以连说话人一起引用。
- **括号里的表演提示会进入口语行**——要么写短，要么放进动作块。
- **标记画外音**（画外：……）。多人在场时，**说清谁在说、谁沉默**；
  **画面上听得见的人不会说别人的台词。**
- ⭐ **物件命名要精确，每次一样**（纸箱快递箱，**绝不这场写"箱子"下场写"包裹"**）
  —— **参考图是按这些词匹配的**。
- **外观留在 profile 字段里，不要每行动作行重复。**

## 四、交接（handoff.md）—— 三层视觉字段的设计很好

| 字段 | 层级 | 内容 |
|---|---|---|
| `visualStyle` | **文档级** | 年代、写实或风格化、调色、光 |
| `visualIdentity` | **实体级·永不改变** | 人：脸、发、体型、标记；地点：布局、入口、材质、地标；道具：形状、比例、细节 |
| `visualState` | **实体级·基线** | 基线服装或陈设 |
| `appearances` | **实体 × 场景** | **只记那一场不同的**：湿透的雨衣、包扎的左手、只亮一盏台灯 |

> **说清哪些细节来自剧本、哪些是你提议的。绝不把虚构的年龄或脸当作作者的。**

**⭐ 我方的对应**：我们有 `entity.description` + `style_note`，
但**没有"实体在某一场景下的状态差异"这一层**。
我们的 `appearances` 等价物是缺失的——**这正好是"同一角色在不同场次要换装/受伤"的场景**。

### 参照图的版本管理（很硬）

> - 绑定结果 **`available` / `relocated` / `ambiguous` / `version-mismatch` / `missing`
>   是五种不同的结果**
> - **绝不因为文件名看着对就绑定或接受一个文件；字节变了就是另一个版本**（比 sha256）
> - **绑定从不移动或删除文件，也从不启动生成**

**我方现状**：`entity_ref.path` 只有一个路径，**没有 sha256、没有版本概念**。
文件被替换了我们不知道。

## 五、可以直接进我们流程的改动

| 我们的现状 | 应该改成 | 依据 |
|---|---|---|
| 门禁只有硬/软两级 | 加**「品味」第三档**——结局基调/钩子类型/视角/风格 **归作者决定，绝不用它阻断** | §一.1 |

| 集间代价没有规划 | 加：**代价要跨集累积；每集末写交接状态** | §三 |
| 结局形状单一 | 加：**变化揭示/反转/决定/安静改变——同一种悬念形状每次用会磨损** | §三 |
| 物件命名无一致性要求 | 加：**同一物件每次用同一个词**（参考图按词匹配） | §三 |
