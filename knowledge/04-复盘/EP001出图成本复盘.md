# EP001 出图成本复盘：从立项到首帧的全部踩坑与代价

**一句话结论：¥30 的图片账里，只有 56% 买到了可入库资产（¥16.8），其余 44% 交给了剧本未验收、沙箱拦截误诊、建筑设定缺失、字幕烧进画面这类"流程性"损耗——而其中大半，是修一次就能永久免掉的。**

数据来源：`data/drama.db` 的 `cost_ledger`（100 笔，合计 ¥30.0）与 `image_generation`（103 条：95 succeeded / 8 failed，失败 3 次计费 ¥0）。单价 Seedream 5.0 pro ¥0.30/张，全程未变。

## 一、剧本未验收就出图 → 16 张作废（¥4.8）

**现象**：10-11 晚按当时的剧本草稿出完 3 个实体 + 8 件道具共 16 张参考图；随后剧本推翻重写，16 张全部作废。

**根因**：出图（第 3 阶段 refs）绕过了第 2 阶段剧本的人工门禁。门禁检查在 `run.py` 里而不在 stage 脚本里，直接跑 `stage_refs.py` 就等于整道门不存在。

**修法（已核对在位）**：
- `pipeline_defs/short-drama.yaml:105` — `script` 阶段声明 `human_approval_default: true`；
- `pipeline/checkpoint.py:153` `guard()` — 两条判据：前面单元必须 `completed`、带人工门禁的必须 `human_approved`，不满足抛 `GateViolation`；
- `pipeline/run.py:158-162` — `run_one()` 先过 `ck.guard()` 再执行，**连 `--dry-run` 也要过门禁**（156 行注释点明：试跑正是最容易跳门的动作）；
- `pipeline/run.py:139-151` — 有门禁的阶段**不打印可执行命令**，不给 agent 绕门的机会。

**复发风险**：agent 拿到用户"先把图出了"之类的指令时，仍可能直接跑 `stage_refs.py --episode-id 1`。gate 只保护走 `run.py` 的路径。

**检查点**：任何出图命令执行前，先跑 `python pipeline/run.py --episode-id N --status`，确认前一阶段是 `[完成]` 且批准列为 `是`；看到 `[等人批]` 就停。

## 二、首帧把台词字幕烧进画面 → 14 张里 7 张重抽（¥2.1）

**现象**：14 张首帧中 7 张把台词文字画进了画面（字幕应在剪辑阶段烧录）。

**根因**：否定约束对画面无效（HANDOFF §十-2 的定论）。提示词里没有"纯影像"的肯定式陈述，模型自由发挥。

**修法（已核对在位）**：`pipeline/stage_firstframes.py:150-154` — `FRAME_SUFFIX = "画面为纯影像状态：画面中没有任何字幕、任何台词文字、任何标题文字与任何水印。"`，在 153-154 行对每镜 prompt 末尾追加，不污染第 6 阶段的库。同款原则也已写进 `pipeline/prompts/portrait.md:19-24`（"写成肯定式，不要写成不要 XX"）。

**复发风险**：改 `stage_firstframes.py` 时若重构掉这段追加逻辑，或从别的脚本出关键帧，都会漏。库里的 `shot.prompt` 本身**不含**这句，只认发送时追加。

**检查点**：出首帧前 `--dump-prompt` 不可用（此脚本无此参），改为核对发送端代码含 `FRAME_SUFFIX`；出图后人工看图时**优先查文字穿帮**。

## 三、模型无视静止锁，遗体坐起 → 重抽 1 张（¥0.3）

**现象**：分镜里 `stillness_lock` 明确"遗体保持平躺"，出图里遗体坐了起来。

**根因**：静态测试过 ≠ 模型每次都遵守。锁是概率性约束，不是硬约束——这是抽卡的固有损耗。

**结论**：单价 ¥0.3 时，**重抽就是正确策略**，不值得为一张图改提示词迭代 10 轮（那才是真浪费）。对照：视频 ¥1.45/秒起，首帧多抽是全链路最便宜的纠错点（`stage_firstframes.py` 文件头 2-6 行就是按这个逻辑写的）。

**检查点**：首帧验收时按"抽卡心态"看：不动大结构的瑕疵直接重抽，别恋战调提示词。

## 四、接口返回 JPEG 存成 .png（keyframe 14 张全中）⚠️ 根因待修

**现象**：`image_generation.local_path` 与 `shot.keyframe_path` 全部记为 `.png`，磁盘上实际是 JPEG。ffmpeg 按内容嗅探所以链路照跑，但严格的读图器会拒读——HANDOFF §八表格与 §九-2 已记过 refs 的同款。

**根因**：`pipeline/stage_firstframes.py:36` `keyframe_path()` 写死 `"E%02dS%03d%s.png"`，第 231 行 `A.download()` 落盘后**没有做内容嗅探校正**，250 行 `UPDATE shot SET keyframe_path=?` 也直接写这个假扩展名。

**对照（refs 侧已修，机制在）**：`pipeline/stage_refs.py:356-364` — 落盘后调 `C.sniff_image_ext()`（`pipeline/common.py:138`），扩展名不符就 `os.replace()` 改磁盘文件名并回写 `rel`。但注意 §九-2 的残留：它改了文件名，`local_path` 列的回写链路曾漏过一版。

**本次处置**：按任务约束**只记录、不改代码**。`stage_firstframes.py` 尚无嗅探逻辑，**根因待修**——修法就是把这 4 行嗅探+回写搬进 `stage_firstframes.py` 的下载后分支（231 行之后），并让 `keyframe_path()` 按嗅探结果定扩展名。

**复发风险**：高。14 张现存 keyframe 的扩展名全是假的，任何按扩展名分派的下游工具都可能炸。

**检查点**：每次批量出图后跑一条内容嗅探审计（对照 `image_generation.local_path` 与实际文件魔数），`.png`/实际 JPEG 不符即报警。

## 五、分镜 LLM 输出变长后 8192 max_tokens 安静截断（4 败 2 次断同处）

**现象**：JSON 解析"偶发"失败；4 次失败里 2 次断在同一位置——这不是偶发，是必然。

**根因**：13 镜 × 转场/出场/五锁，每镜约 500 字，默认 `max_tokens=8192` 装不下，输出被**安静地截断**，错误报在 JSON 解析层，与真实出错点（token 上限）隔着一层。

**修法（已核对在位）**：`pipeline/stage_storyboard.py:394-396` — `L.chat_json(..., max_tokens=16384)`，且 390-393 行注释写明判据："看起来像偶发，实际每次都断在同一处。16384 给足余量；模型按实消耗计费，设大不等于多用。" 默认值本身在 `pipeline/llm.py:67`（8192），是调用方显式覆盖的。

**复发风险**：其他 `chat_json` 调用点（entities、script）若输入规模继续涨，8192 会再炸一次。

**检查点**：**判据复用**——同一位置断两次就是必然不是偶发，立刻怀疑 token 上限/上下文截断，而不是重试碰运气。新增长输出调用时默认给 16384。

## 六、INSERT 28 列 positional 占位符数错（29 values for 28 columns）

**现象**：分镜落库时报 `29 values for 28 columns`。

**根因**：`shot` 表 28 列，手写 positional `?` 占位符在列太多时数错一次就炸一次，且每次改列都得重数。

**修法（已核对在位）**：`pipeline/stage_storyboard.py:287-326` `persist()` — 291-292 行注释点明原因；`vals` 字典列名与键名一一对应，322-323 行 `cols = ", ".join(vals)`、`marks = ", ".join(":%s" % k for k in vals)` 生成 `:key` 具名绑定，加列只需加字典项，数数这件事交给机器。

**复发风险**：低——但仅限此函数。其他长 INSERT 若图省事用 positional，会重演。

**检查点**：SQL 参数超过 5 个一律具名绑定；schema 加列后跑 `tools\verify.py`（HANDOFF §八记过 schema.sql 与迁移列顺序不一致踩了 3 次）。

## 七、沙箱写 D:\dsh-film 报 Errno 13 被误诊 → 白烧 9 笔 ¥2.7

**现象**：两次批量出图各有一批「已计费·未落盘」（id 30–34、51–54）：模型已经扣费，文件因 `Errno 13` 写不进 `D:\dsh-film`。

**根因**：DSH 文件沙箱**故意拦截**工作区外的写入——这是设计行为，不是 ACL 坏了。第一次误诊为权限损坏，跑了一次 ACL 修复，白费时间；第二次才意识到正解。

**修法**：出图/落盘/恢复类命令**一律带提权**（danger-full-access）发起，不要在受限会话里反复试写。判断依据：目标是沙箱白名单外的路径 + 报错是拒绝访问 → 先想"故意拦"，再想"坏了"。`diagnose-windows-sandbox-acl` 技能也明确写了：**预期内的隔离拦截不需要 ACL 修复**。

**检查点**：任何要写 `D:\` 的命令，发起前先确认会话权限；见 Errno 13 先问"这路径在白名单里吗"，别修 ACL。

**附带教训**：这两批钱没全白烧——URL 存进了 `image_generation.image_url`（`stage_refs.py:349-350` 的提示也是这么写的），**已计费未落盘的图可以凭 URL 重试下载，不必重新生成再付费**。

## 八、--only 参数重复传只吃最后一个（argparse 行为）

**现象**：想一次重出多张，写成 `--only 3 --only 8 --only 10`，实际只处理了 10。

**根因**：argparse 对普通（非 action）参数重复赋值只保留最后一个。`stage_firstframes.py:111`、`stage_refs.py:405` 的 `--only` 都是单值参数。

**修法**：不改代码（行为是标准库的）。用法纪律：**重出多张要么逗号列表一次传**（`--only 3,4,5`，`stage_firstframes.py:137` 按逗号切），要么分次跑。配合 `--force`（113 行，已有首帧也重出）与实体重出的 `--only 名字 --force`（`stage_refs.py:405-408`）。

**检查点**：重出命令发出前数一遍 `--only` 出现次数，>1 就是错的。

## 九、三间房不像一栋楼 → 根因"只有房间没有建筑"

**现象**：殡仪馆整容室、后廊、焚化车间三张场景图风格各说各话，门/天花/灯具对不上，观众一眼看出不是同一栋楼（cost_ledger 45–50 作废、55–64 重出，净损 ¥1.8 + 9 张重出）。

**根因**：每个 location 的描述独立生成，模型各编各的公共元素。缺的不是提示词技巧，是**建筑层的信息**。

**修法（已核对在位）**：
- 项目档案新增「## 建筑设定」章，把同栋楼公共元素（门款、天花、灯具、墙面）一次定死；
- `pipeline/stage_entities.py:216-227` `parse_arch_spec()` 用正则 `^##\s*建筑设定` 抽出该章，243 行在 `build_prompt()` 里注入，247 行作为 `$arch_spec` 进模板；
- `pipeline/prompts/entities.md:72-78` 模板明文要求：`$arch_spec` 非空时**所有 location 描述必须照抄公共元素，不许各编各的**；
- `tools/prompt_review.py:380-399` `check_arch_consistency()`：按 `ARCH_ELEMENTS` 关键字对每个 location 查"写了 vs 没写"，两边都非空即报不一致；434-435 行把它作为独立一步跑在出图前。

**复发风险**：新剧的项目档案忘了写「## 建筑设定」章，`parse_arch_spec` 返回空串、静默跳过——链路不会报错。

**检查点**：出场景图前确认项目档案有该章且非空；`tools/prompt_review.py` 的建筑一致性告警清零再出图。

## 十、道具乱码假字 / 材质错 / 刻字缺失 → 改根因再单体重出

**现象**：黄铜签牌出两次都是乱码假字（id 76、78 两次重出），口部塑形器材质错，死亡确认书刻字缺失。

**根因**：错误出在**实体描述**（材质/文字内容写得不够具体可执行），不是抽卡运气。呼应 HANDOFF §五追加教训：「用效果替换具体」模型只能自由发挥；「需要遮挡的地方删掉而不是替换」模型会自己塞东西。

**修法**：**改 entities 里的实体描述根因 → `stage_refs.py --only <实体名> --force` 单体重出**，绝不改图（改图=不进库、下集重演）。出图前的守门人是 `tools/prompt_review.py` 的逐实体审查（402-435 行）。

**检查点**：道具图不合格先问"描述里文字内容写死了吗、材质是可执行的具体物吗"，改描述再出；`--only` 传**名字**不是 id。

## 出图前 checklist（跑图前过一遍，防 a/b/d/e 类）

1. **门禁**：`run.py --status` 确认剧本/分镜等上游门禁全是 `[完成]` + 批准 `是`；有 `[等人批]` 就停（防 a）。
2. **提示词尾缀**：确认首帧发送端带 `FRAME_SUFFIX` 纯影像句（防 b）。
3. **建筑设定**：项目档案「## 建筑设定」章存在且非空；`prompt_review.py` 建筑一致性零告警（防 i）。
4. **实体描述**：文字内容逐字写死、材质是可执行的具体物；有假字史的道具优先核对描述（防 j）。
5. **max_tokens**：长输出 LLM 调用显式传 16384；"偶发"解析失败先查是否断在同一处（防 e）。
6. **扩展名**：出图后对 `local_path`/`keyframe_path` 做一次内容嗅探审计；stage_firstframes 根因未修前，这步不能省（防 d）。
7. **权限**：写 `D:\dsh-film` 的命令带提权发起，见 Errno 13 先想"故意拦"（防 g）。
8. **--only**：逗号列表一次传，不重复传参；多镜重出配 `--force`（防 h）。
9. **记账**：确认 `price_book` 有单价，不按 0 记账；「已计费·未落盘」的图凭 `image_generation.image_url` 重下，不重复付费。
